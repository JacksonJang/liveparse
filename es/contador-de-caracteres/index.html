Una cadena, varias longitudes correctas

Define qué significa «carácter» antes de aplicar un límite

Al escribir, una persona suele esperar que una letra acentuada o un emoji unido cuente como una unidad y no se corte por la mitad. La frontera práctica utilizada para aproximar esa unidad visible es el grafema extendido. Es una aproximación a un carácter percibido, no una garantía de que todas las tipografías, lenguas o tareas de edición representen cada secuencia del mismo modo.

Un punto de código es un valor del espacio Unicode, como U+00F1 para ñ o U+1F600 para 😀. Las cadenas de JavaScript añaden otra capa: están formadas por unidades de código UTF-16 de 16 bits. Un punto situado por encima de U+FFFF necesita un par suplente; por eso "😀".length devuelve 2.

Al guardar o transmitir el texto aparece una cuarta longitud: los bytes UTF-8. Un campo de interfaz limitado por grafemas, una API JavaScript limitada por unidades UTF-16 y una columna limitada por bytes pueden aceptar cantidades distintas del mismo texto. «Máximo 280 caracteres» no es un contrato completo si no nombra la unidad y la política de normalización.

Una frontera definida por Unicode

Intl.Segmenter agrupa marcas, modificadores y emoji unidos

El total principal utiliza Intl.Segmenter con granularidad de grafema. El Anexo Unicode #29 describe las reglas predeterminadas de grafemas extendidos, incluidas las marcas combinantes, los modificadores de tono de piel, los indicadores regionales de banderas y determinadas secuencias con unión de ancho cero. ECMA-402 define cómo JavaScript expone esa segmentación.

Los datos de frontera pertenecen al motor del navegador y pueden actualizarse con nuevas versiones de Unicode. Editores especializados también pueden imponer reglas propias. Si una decisión debe reproducirse de forma exacta, conserva la cadena original y registra el entorno que calculó el total.

Un grafema tampoco mide anchura visual. Puede ocupar una columna estrecha o ancha, combinarse con vecinos, no mostrar tinta o aparecer como un glifo ausente. Un límite de diseño necesita medir la fuente y la composición, además de contar la cadena.

Con espacios y sin espacios

La métrica «sin espacios» excluye grafemas de espacio en blanco, no modifica el texto

El total de grafemas incluye espacios, tabulaciones y saltos de línea porque son parte de la cadena. El total «sin espacios» revisa cada grafema y excluye solo los que están formados enteramente por caracteres que JavaScript reconoce como espacio en blanco Unicode. No borra nada de la entrada y no recalcula puntos de código, UTF-16 ni UTF-8 sobre una copia modificada.

Esto evita confundir la ausencia de tinta con la ausencia de estructura. Un salto de línea sigue separando líneas aunque no contribuya al total sin espacios. Una unión de ancho cero dentro de un emoji no es un espacio que deba eliminarse: pertenece a la secuencia gráfica que ayuda a formar el grafema.

La herramienta cuenta líneas lógicas. El valor vacío tiene cero; cuando hay texto, un salto final crea una línea vacía adicional. Se reconocen LF, CR, CRLF, NEL, U+2028 y U+2029, aunque el control textarea convierte CRLF y CR en LF antes de entregar su valor a JavaScript.

Entrada actual, codificación estricta

La normalización y los suplentes aislados cambian la pregunta de bytes

No se aplica NFC, NFD, NFKC ni NFKD al valor actual. El área de texto HTML ya ha convertido CRLF y CR en LF, de modo que una comparación exacta con los bytes de un archivo debe tener en cuenta esa transformación. Normaliza solo cuando el protocolo receptor exija una forma determinada; firmas, hashes y claves deben seguir sus propias reglas.

Una cadena JavaScript puede contener un suplente alto o bajo sin su pareja. Ese valor ocupa una unidad UTF-16, pero no es un valor escalar Unicode y no tiene una codificación UTF-8 directa. TextEncoder convierte esos suplentes aislados en U+FFFD al aceptar un USVString.

Los tres bytes del carácter de sustitución son útiles para interoperar, pero no conservan el valor original. Por eso este contador marca los bytes UTF-8 estrictos como no disponibles cuando detecta un suplente aislado, en lugar de presentar silenciosamente la longitud de una cadena reparada.

Inspección local

Privacidad y capacidad de la herramienta

El análisis se ejecuta en un proceso dedicado dentro de esta pestaña. LiveParse no envía intencionadamente la cadena introducida a un servicio de recuento, no la coloca en la URL y no guarda un historial del documento en almacenamiento local. Esto resulta útil para borradores, identificadores y ejemplos que no deberían copiarse a una API desconocida.

El procesamiento local no aísla el dispositivo: extensiones del navegador, utilidades del portapapeles, software de accesibilidad, capturas, informes de fallos y el sistema operativo quedan fuera del control de la página. Elimina secretos que no necesites medir y sigue las normas aplicables al equipo.

La entrada admite como máximo 200.000 unidades UTF-16 para impedir que una sola operación bloquee la pestaña durante demasiado tiempo. Ese máximo técnico no modifica el texto ya aceptado y no describe la capacidad de ninguna red social, API o base de datos.

Preguntas frecuentes

Dudas sobre el contador de caracteres

¿Qué significa carácter en este contador?

El total principal cuenta grafemas extendidos, una aproximación a los caracteres que percibe una persona. La herramienta muestra además puntos de código Unicode, unidades de código UTF-16 de JavaScript y bytes UTF-8 para que puedas aplicar la unidad que especifique el servicio de destino.

¿Por qué una letra con tilde o un emoji puede tener varias longitudes?

Una ñ precompuesta puede ocupar un punto de código, mientras que n seguida de una tilde combinante ocupa dos; ambas pueden formar un solo grafema. Un emoji visible puede combinar varios puntos de código mediante modificadores, indicadores regionales o uniones de ancho cero.

¿Los espacios y saltos de línea cuentan como caracteres?

Sí, forman parte del total de grafemas. La métrica sin espacios excluye los grafemas compuestos enteramente por espacio en blanco Unicode, como espacios, tabulaciones y saltos de línea. No elimina espacios del texto ni cambia las demás métricas.

¿Cuál es la diferencia entre un punto de código y una unidad UTF-16?

Un punto de código es un valor del repertorio Unicode. Una unidad UTF-16 es uno de los valores de 16 bits que forman una cadena ECMAScript. Los puntos de código superiores a U+FFFF usan un par suplente y por eso ocupan dos unidades UTF-16.

¿El límite personalizado se mide en bytes?

No. El límite personalizado se mide en grafemas y muestra cuántos quedan o cuánto se ha excedido. No recorta ni modifica la entrada. Si una API o base de datos limita puntos de código, unidades UTF-16 o bytes UTF-8, debes consultar la métrica correspondiente.

¿Se sube, se guarda o se normaliza mi texto?

El cálculo se ejecuta en la pestaña actual y LiveParse no envía intencionadamente el texto a un servicio de recuento ni conserva un historial del documento. No aplica normalización Unicode. El área de texto HTML sí convierte los finales de línea CRLF y CR en LF antes del análisis.
